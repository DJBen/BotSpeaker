The processing path begins when the meeting service emits a completion event containing the recording and transcript identifiers, organization policy version, participant-notice result, language, and regional routing key. An admission service verifies that the organization and organizer enabled Decision Digest, that notice succeeded, and that the meeting type is in scope. It then writes a durable job without copying media. Workers retrieve the transcript from its source region, divide it into overlapping semantic windows, generate candidate decisions and actions, and run a grounding pass that requires a timestamp range for every item. A final assembler removes duplicates, preserves uncertainty labels, and writes the digest back to the meeting record. The worker never needs access to unrelated meetings or the customer’s task systems.

Reliability during the pilot was ninety-nine point six two percent successful completion across thirty-two thousand jobs. Most failures were transient model-provider timeouts and were recovered by bounded retry. Twelve jobs required manual replay after a regional queue configuration was deployed with the wrong concurrency limit. We have since moved queue limits into the versioned service configuration and added a deployment check that compares desired and observed values by region. Jobs are idempotent: a retry uses the same job identity and replaces an incomplete draft instead of creating duplicates. The dead-letter queue alerts after three failed attempts, and the operator view shows the policy version, processing region, error category, and safe replay action without exposing transcript content in logs.

Latency is the main engineering risk. Median generation is six point two seconds for a sixty-minute meeting, but the ninety-fifth percentile is fourteen point eight seconds and the ninety-ninth percentile reaches twenty-seven seconds. Profiling shows that long transcripts create many small inference requests, increasing queue overhead and reducing cache efficiency. The batching change groups compatible transcript windows while preserving organization and region isolation. Replay against the last ten thousand pilot jobs reduced the ninety-fifth percentile to ten point nine seconds and the ninety-ninth percentile to seventeen point four seconds, with no statistically significant quality regression. Before launch, we will run it in shadow mode for forty-eight hours, compare output hashes and grounding scores, then enable it for one internal canary organization.

Capacity planning assumes the first cohort produces twenty thousand meetings per week, with a fivefold peak during weekday afternoons. The current regional pools can handle eight times that initial peak while keeping thirty percent headroom, but shared model-provider quotas are a possible bottleneck. We have reserved capacity for the first two rollout stages and implemented per-organization fairness so one large import cannot starve interactive jobs. When saturation approaches, admission will queue work and show a delayed status rather than dropping jobs or routing content outside the configured region. The kill switch stops new admissions immediately and lets in-flight jobs either finish or move to a policy-defined cancellation state. We will test both paths before launch.

Grounding is implemented as an enforceable output contract. Every decision and action must include at least one transcript span, speaker attribution when available, and a confidence category. An unsupported item fails assembly and is omitted. The user interface can still expose the transcript segment even if speaker diarization is uncertain. We monitor unsupported-candidate rejection, attribution correction, edit distance, and user deletion by language. Quality samples are reviewed blindly each week, and any substantiated unsupported decision opens a severity review. The system prompt and model version are recorded with the digest so we can reproduce behavior. Model changes use the same staged rollout as application changes and cannot bypass the quality suite.

The four-language launch requires separate evidence. English and Spanish exceed the agreed precision threshold. French is within two points of English. German action-item recall is lower because modal phrasing is often interpreted as discussion rather than commitment. Precision remains high, so the system is not inventing more actions; it is omitting some. We have added language-specific examples and a classifier change that improves replay recall by four points. I support the Product Manager’s proposal to label non-English summaries as beta, but only if the readiness dashboard remains segmented. Aggregate metrics can conceal a language regression, and expansion should pause for the affected language without disabling healthy regions or English processing.

Data deletion is designed as an event-driven workflow. Deleting a meeting or digest creates a signed deletion request that removes the digest, derived embeddings, temporary transcript windows, and cached inference artifacts. Each subsystem acknowledges completion, and the control plane reports whether the documented deletion window was met.
